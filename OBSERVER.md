## Real objective and hard boundaries

Improve **semantic correctness** of SQL generated by the fixed **Qwen3.5-9B** baseline. Main endpoints: BIRD strict SET/BAG execution match, case-level wrong→right rescues and right→wrong regressions, candidate-generation vs selection failures. Mere executable SQL, valid syntax, higher tool success or nominal CI success **do not count** as semantic gains. Keep BIRD DEV100, DEV500, TRAIN48, TRAIN240 and HOLDOUT300 as **distinct populations**; never pool numerators/denominators or equate their metrics.

**Current authorization is read-only**: no default pipeline edits, no SQL rewrites, no code changes, PRs, experiments, GPU, Qwen inference, training or QLoRA without explicit new owner permission. Qwen3.5-9B is fixed; current SQL research track has **NO TRAINING** authorization for Observer. Do not open sealed **HOLDOUT300** or the two historically unexposed BIRD TRAIN physical databases `simpson_episodes` and `works_cycles`. Prior general research policies allowing conditional future training are **not** permission to train in this review.

## Per-review protocol

1. Read `OBSERVER.md`, newest `docs/observer/audit-*.md`, `NOW.md`, `IDEAS.md`, `docs/pro-research-gates.md` and source PRs; then fetch latest PR/commit SHA, Actions, job states, logs and artifacts live.
2. Explicitly mark **verified / Executor-reported / inferred / not identifiable**. Validate file hashes, source selection, stage ordering (questions/schema before model SQL; labels after SQL), and correct vs wrong vs censored case joins. Successful CI proves code ran, NOT semantic validity.
3. Verify actual denominator and the **reachable intervention branch** before using a cohort to assess mechanism performance. Never call 0 false-positive flags meaningful precision when the rule abstains on everything.
4. Separate question intent, entity identity, relationship/direction, predicate/filter and population scope, grouping/aggregation grain, ratio numerator/denominator, output projection and ordering. Distinguish **candidate generation failure** from **candidate selection failure**, and from scorer/DB execution issues.
5. Challenge source-only lexical candidate labels; a question string matching `how many` may ask for per-day average or a list. PK/FK grounding is a **candidate**, not an independent semantic truth label. SQL EX wrong is not proof of any one semantic error class.
6. Protect right-original cases: paired rescue/regression, multiple physical DBs, unambiguous independent semantic review and one prospective **source-disjoint** falsification test before recommending any costly A/B. No post-label threshold tuning, cherry-picked known-wrong tests, blanket `COUNT(DISTINCT)`, or unreviewed use of sealed data.
7. Track new completed **official** results separately from partial/running jobs and note timestamp. If no material verified change, say **NO NEW EVIDENCE** and stop; do not invent improvement.
